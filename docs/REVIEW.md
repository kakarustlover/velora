# گزارش بازبینی (بعد از نوشتن کد)

## چی بررسی شد
1. `scripts/lint.py`: همه‌ی `set_/get_/on_` سمت Rust با `AppState` تطبیق داده شد؛ هر ۳۲ کال‌بک یک هندلر Rust دارد؛
   هر `AppState.x / Ic.x / Theme.x / Pal.x` در Slint تعریف شده؛ تعادل `() {} []` در همه‌ی فایل‌ها؛
   نام و کد دستورهای JNI بین Kotlin و Rust یکسان است.
2. فرمول‌های معادل‌ساز با NumPy: پیک +۶dB دقیقاً ۶٫۰۰۰، شلف‌ها ±۰٫۰۱dB، همه‌ی قطب‌ها داخل دایره‌ی واحد (حداکثر ۰٫۹۹۹).
3. هندسه: `art2`، مینی‌پلیر، صفحه‌ی پخش، شیت‌ها و More با اعداد مرورگر مقایسه شد.

## ایرادهایی که همین بازبینی پیدا و رفع شد
* خطای borrow-checker در `on_row_tapped` (نوشتن در صف هم‌زمان با خواندن لیست).
* نام تکراری پراپرتی/کال‌بک `eq-preset` در Slint → `eq-pick-preset`.
* struct هم‌نام با المان داخلی `Row` → `ListRow`.
* callback به اسم `changed` روی اسلایدرها (تداخل با `changed prop =>`) → `value-changed`.
* `x/y` روی فرزندان Layout، جمع `string + int`، نوع `float` به‌جای `length`.
* تایمر ۵ ثانیه‌ی حلقه‌ی دور دکمه، آهنگ بعدی رو زودتر خاموش می‌کرد → شماره‌ی نسل.
* اختلاف ۸px عنوان/محتوای شیت‌ها، ارتفاع ردیف‌های تنظیم (۶۰/۶۹)، ابعاد More (۸۸ / ۱۲۴٫۳ / ۷۵).

## چیزی که تأیید نشده (باید با بیلد واقعی دید)
* کامپایل Rust/Slint/Kotlin (ابزارش در محیط من نبود).
* رفتار واقعی لمس، سرعت اسکرول و فریم‌ریت روی دستگاه، Android 14/15 foreground-service.
* نقاط پرریسک Slint: `absolute-position`، `rotation-angle` روی Image، `changed viewport-y`، `Path.commands` پویا،
  گرادیان با زاویه‌ی محاسباتی. اگر کامپایلر هر کدوم رو نپذیرفت، راه‌حل جایگزین:
  - `absolute-position` ← پاس دادن صریح x/y المان به `Glass`؛
  - `rotation-angle` ← حذف چرخش دیسک (فقط ثابت)؛
  - `changed viewport-y` ← Timer کوتاه که `viewport-y` رو بخونه؛
  - `Path.commands` پویا ← آیکون‌های ثابت جدا (متن literal).
